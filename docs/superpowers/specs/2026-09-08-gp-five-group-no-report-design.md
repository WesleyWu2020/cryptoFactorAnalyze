# GP 五分组、无报告运行设计

## 目标

为全量日频 GP 运行提供一个可复现的五分组、无 HTML 报告模式；默认只完成
2024 年训练、2025 年验证和冻结。仅当操作者显式设置 `GP_RUN_TEST=1` 时，才
访问一次 2026 年独立留出集。

## 边界与数据流

`tmp/run_full_daily_gp.sh` 负责创建新运行目录、执行 `audit`、`search`、
`validate` 和 `freeze`。默认配置将回放分组数记录为 5，并禁用 HTML 渲染。
回放仍然持久化用于认证指标的中间评估；脚本在所有被请求的阶段结束后删除
仅属于本运行目录的 `factor_results/`。

当 `GP_RUN_TEST=1` 时，脚本在冻结后调用 `test --manifest frozen.json`。测试会
评估所有已冻结候选，而不是利用 2026 年结果重新排序、再选择或重新搜索。
测试收据保留在 `test_receipts/`；通过名单由测试收据和 2025 验证产物共同确定。

## 配置与兼容性

将回放参数 `n_groups` 与 `render_reports` 作为受校验的 GP 配置字段，并写入
不可变的 `config.json` 与冻结 profile。现有配置维持 10 分组、渲染报告的默认
行为；脚本改用新增的五分组、无报告配置，避免改变已有实验的语义。

当 `render_reports=false` 时，回放不调用 HTML 渲染方法，产物中的 `report_path`
为 `null`。回放仍会记录全成本指标、因子路径、元数据路径和运行 ID。

## 验证

新增测试覆盖配置校验、五分组参数透传、无报告时不调用渲染，以及脚本的静态
命令与清理顺序。运行现有 GP 配置、回放和 CLI 测试；用 shell 语法检查脚本。

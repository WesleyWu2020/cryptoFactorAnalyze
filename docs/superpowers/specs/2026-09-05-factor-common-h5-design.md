# 日频因子公共框架与 H5 迁移设计

日期：2026-09-05

## 1. 目标与范围

在 `factor_common` 实现本项目自己的标准化底层，参考 `reference/use.ipynb` 的调用规范，复用已有因子分析能力。首期交付公共层、新因子模板、一个 N 日动量示例及从 H5 到 Parquet、回测、HTML 报告和 Notebook 查看的一条完整链路。

本次不批量迁移其他因子，不实现公式字符串解释器、ML/GA 调度、批量提交审批、Barra 模型或分钟行情。参考项目仅提供接口示例，不能声称已复现其内部算法。现有 H5 是 UTC 日频，不支持 4h/8h 回测。

已确认：重构底层并保留旧调用兼容性；可以修正已有计算口径，但必须记录差异；默认 t 日收盘生成信号、t+1 日开盘执行；资金费计入默认回测成本。

## 3. 模块职责

`factor_common` 使用以下聚焦模块，不复制参考项目的多层 services/plugins 目录：

- `manager.py`：`FactorManager` 协调计算、保存、评估及绘图，不放指标公式。
- `data_provider.py`：复用现有 reader/store，提供字段查询、时间范围、字段矩阵、成分池、资金事件与质量信息。
- `definitions.py`、`loader.py`：验证元信息、设置、结果轴、因子标识和模块加载。
- `value_engine.py`：预热、调用 `calc_factor`、按日预处理与输出裁剪。
- `storage.py`：Parquet、元信息、运行结果的原子落盘和读取。
- `profiles.py`：交易与成本配置；因子公式参数不进入交易 Profile。
- `backtest.py`：订单、持仓数量、价格损益、交易费和逐事件资金费账本。
- `metrics.py`：从账本及标签计算 IC、收益风险、换手和覆盖率等指标。
- `reporting.py`、`templates/`：统一结果到 HTML 和 Notebook 展示，不重新回测。
- `validation.py`：结构、数据质量及 cutoff 未来函数验证。

可根据依赖实际规模合并小模块，但数据加载、因子计算、交易账本与展示必须独立。仅沿用 pandas、NumPy、SciPy、PyTables、现有 Parquet 后端及 pyecharts 等现有栈。

## 4. 对外接口

目标接口：

```python
from factor_common import FactorManager

fm = FactorManager(h5_path="data/crypto_quant.h5", base_dir="data/factor_results")
result = fm.evaluate(
    "factor_analyse/factor_mining/example_momentum.py",
    profile_id="perp_1d",
    params={"start": "2024-01-01", "end": "2026-09-04"},
    plot=True,
)
```

首期支持 `.py` 路径和 DataFrame 因子输入，`create_template()`、`get_value()`、`get_performance()`、`plot_result()` 及 `fm.dp` 数据查询。DataFrame 支持标准长表或日期×标的矩阵，保存时必须提供显式因子名称；对调用者提供的数据标记为外部因子，不能声称验证了其计算过程无未来函数。

`evaluate()` 返回标准字典：`factor_value`（最终日频矩阵）、`factor_performance`（全样本/样本内/样本外指标）、`factor_result`（带真实日期的收益、分组、换手、覆盖率、持仓与费用序列）、`diagnostics`、`metadata`、`paths`。未执行标准化时不伪造 raw/processed 两套结果；元信息明确 preprocessing 配置。最新持仓/信号查询使用与回测相同的分组与方向规则。

结果包含 `status=complete|incomplete|insufficient_data`。不完整时仍可返回因子值、诊断及有效段账本，但完整净收益绩效为缺失并说明原因，不用跳过缺失日期的累计值冒充完整回测。

## 5. 因子定义与数据契约

模板包含 `TYPE="regular"`、`META`、`SETTING` 和 `calc_factor(data_ctx)`。META 包含稳定标识、作者、描述、分类与 `level="daily"`；SETTING 包含所需字段、预热天数、历史成分池、显式预处理方法和因子参数。不得把参考示例中的 1440 根分钟窗口直接当本项目默认窗口。

输入字段统一为日期×标的矩阵，UTC 日期索引与标的列一致。按自然日补齐索引，缺失行情保留 NaN；不 bfill，不跨缺口把后一条行情当下一日。价格非正、非有限值和零成交量行情的不可执行状态应明确校验。因子计算可保留上市后的历史窗口，但输出、截面排序及标准化仅用当日已知成分与有效数据；不能用未来入池信息改变历史横截面。

预热数据从 start 之前加载且不计入输出；滚动计算先于输出池过滤。字段可用性按依赖判定，价格因子不因资金费缺失而整天被剔除。原 reader 中要求整个日期所有标的 K 线和资金费完整的默认筛选不能直接用于该计算链路。

示例为 N 日动量，复用旧公式和适用的按日处理，去除标签对因子输出的影响。因子值只依赖 t 及之前数据；因子方向预先配置，不根据全量收益翻转。

## 6. 落盘与可追溯性

单因子标准长表保存在 `data/factor_results/<factor_id>/<value_run_id>/factor.parquet`，列为 `date、instrument、factor`，键唯一且稳定排序。对应 metadata 保存公式源码摘要、参数、计算范围、预热、预处理、数据版本/指纹及框架版本。不同参数或数据快照不能静默复用旧结果。

每次评估保存到该运行目录下 `evaluations/<evaluation_id>/`，记录 Profile、账本、指标和诊断；调仓或成本变化不覆盖因子 Parquet。HTML 继续输出到 `reports/`，文件名包含因子、调仓周期和运行标识。采用临时文件再原子替换，失败运行不更新成功结果指针。查询允许指定运行标识，默认取最新成功结果；不存在时明确报错。

## 7. 交易时序与收益

默认日频 Profile：10 组、正向因子买最高组卖最低组，反向交换；同值用固定标的次序稳定分组。标的不足以组成有效双边组合时记录不可评估，不能悄悄改变多空定义。默认多空各占净资产 50%，组内等权，合计总名义敞口 100%；多头单独组合另行统计。初始净值为 1，默认单边交易费率 0.0003，可显式修改。

t 日收盘生成信号，t+1 日开盘执行。N 日调仓由明确日期锚点和自然日周期决定，锚点保存在 Profile/运行元信息，不能因为展示窗口变化而改变持仓历史。交易后持仓数量保持到下一次成交，逐日记账，不能把重叠 N 日标签逐日复利为组合净值。信号延迟、执行字段、调仓周期、总敞口、手续费、资金费模式、样本切分均写入 Profile。

日账本以相邻 UTC 开盘为边界，先处理边界时刻资金费，再执行订单。t 信号对应从 t+1 开盘到 t+N+1 开盘的 IC 标签；标签只进评估层。end 指最后信号日，评估按持仓周期额外请求所需尾部行情；没有足够尾部数据的信号仍保存，标签不可评估且报告实际可评估区间。起始无持仓，不收取起始前资金费；结束采用明确平仓并计费约定，终点资金结算先于平仓。

收益账本分列价格损益、交易费、资金费与净资产，展示未扣费、仅扣交易费、全成本三条可核对序列；费用按对应账本持仓计算，不混用不同资金路径。基于日净值年化使用 365。交易手续费为实际成交绝对名义金额乘费率，包含建仓和平仓，换手定义与费用公式同时记录。

缺价的新订单不成交并报告原因；已有持仓缺估值价、下架无法退出时停止该段完整绩效认证，不删除持仓或假定零损失。首期不模拟盘中清算、盘口冲击与保证金机制，报告说明这些边界。

## 8. 资金费

资金费默认启用，使用 `funding_events` 的实际时间戳逐笔结算，不假定每天固定三次。现金流为 `-signed_quantity * mark_price * funding_rate`；正费率多头付空头收，负费率相反。结算同刻先对旧持仓计费，再执行开盘调仓，这是本框架明确的边界约定。

2026-09-05 只读核查：547,193 条事件，资金费率无 NaN；mark_price 有 25,617 条 NaN、3 条非正值，rate_type 均为 Regular。数据缺陷只影响实际持仓覆盖的事件区间，不阻止无关因子值计算。

默认 strict 模式：持仓遇到无效结算价或已知资金费覆盖缺口时，结果为 incomplete，拒绝完整净绩效。结合现有 panel 的资金费完整性标记与事件数据检查覆盖；不能单凭“已有事件都有费率”断言没有遗漏，也不能自行按三次/日填记录。覆盖证据不足同样列为未验证。

提供显式 `funding_price_mode="daily_open_approx"`：仅当已存在事件缺结算价时，用该事件之前或同时可得的当日有效开盘价估值，并逐笔记录替代原因及受影响金额。不使用当天收盘价估值此前事件，不以近似模式填补缺失资金费率或缺失事件。报告清楚标记近似，无法解释为交易所账单级复现。默认示例仍按 strict 执行；完整端到端验证选择资金费和行情完整的真实区间，另用坏数据测试验证失败路径。

## 9. 指标与报告

保留已有 IC/RankIC、IR、分组收益、多空收益、换手、年化收益与波动、夏普、回撤、胜率、盈亏比、IC 衰减、自相关及样本内外分析。新增明确的覆盖率、资金费收支、交易费、可评估区间和数据质量摘要。单一公共函数处理不同样本，不继续复制全样本和分样本代码。

默认最后 180 个自然日为样本外，支持显式 split_date；跨越边界的 IC 标签从分样本统计中排除。组合账本连续计算，分样本净值由同一账本切片并重置展示基点，不在样本外开头隐式重新建仓。样本不足时明确说明，不伪造样本外统计。

报告模板只消费结果；plot=False 仍返回全部指标，重新绘图不重跑交易。时间索引来自真实数据，禁止按长度人工造日期。CMC100 可作为可选基准，明确其指数口径，与旧市值50等权指数不是同一序列，不偷偷替换同名曲线。

旧实现的全区间恒定因子币种剔除不进入新历史选币逻辑；旧对数/简单收益混用、缺日行位移、费用硬编码等问题逐项记录新旧差异。按相同输入、相同数学口径对照可复用指标；有意修正不以数值完全相等为验收目标。

## 10. 验收与实施分段

按依赖实施：数据契约和 Profile → 因子模板/值引擎/Parquet → 持仓与资金费账本 → 指标和报告 → 旧入口适配 → 示例与 Notebook。每段属于同一实施计划，但可单独验证。

必要验证：

1. H5 字段、历史成分边界、缺日、预热、仅价格因子资金费缺失等数据测试。
2. 示例因子禁止模式静态扫描，列出负 shift、居中 rolling、bfill、forward asof 的位置和用途；全量与多个 cutoff 的因子值及输出成员一致，max_abs_diff 为 0 或明确浮点容忍范围。截断必须同时作用于市场与成分信息。
3. 可手算交易样本验证次日开盘执行、N 日持仓、同刻资金结算与调仓顺序、正负费率、持仓漂移、初次建仓及结束平仓费用。
4. 缺失 mark_price、非正价、缺费率/事件、缺执行价、下架持仓、空结果及标签尾部不足的诊断测试。
5. Parquet 往返、参数隔离、数据指纹变更、重复键、原子保存和旧 CLI/构造契约测试。
6. 同一结果的 HTML 与 Notebook 指标一致，报告明确手续费和资金费；真实 H5 选择完整窗口执行默认 strict 的示例端到端验证，完整区间选择仅用于工程验证，不能用作无偏策略绩效证明。
7. 使用 `./.venv/bin/python`，运行相关测试、语法/导入检查和受影响 reader 回归；输出变更清单、执行命令、产物路径及已知限制。
